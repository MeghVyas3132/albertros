npm supply-chain checker

Know which dependency will hurt you, before npm install does.

Albertros checks every package against npm's own takedowns, the OSV malware database, the signals of a hijacked release, and the published code itself. It runs in your browser and uploads nothing.

    Four checks, one verdict

    Every package gets Danger, Review or Safe, with the reason in plain language.

    01

    Takedowns and missing names

    Names npm replaced with a security placeholder, versions pulled from the registry, and private-looking names that don't exist on npm, which anyone could register (dependency confusion).

    02

    Known malware and vulnerabilities

    Every exact version is matched against OSV, which includes the OpenSSF malicious-packages feed and GitHub advisories.

    03

    Signs of a hijacked release

    A first release by a new account, an install script that wasn't there before, CI provenance that suddenly stops, a sudden size jump, or a release only hours old. The chalk/debug and Shai-Hulud attacks set off several of these at once.

    04

    The code itself

    Downloads the published tarball and looks for what real attacks do: scripts that run on install and reach the internet, hidden eval, token and SSH-key theft, wallet hijacking, obfuscation.

    Same engine in your terminal and CI

    Fails the build when a dependency is dangerous. Exit code 1 on danger, 0 when clean.
